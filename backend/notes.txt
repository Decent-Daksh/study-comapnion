Operating systems manage hardware resources and provide services for application programs. The kernel is the core component that has complete control over the system, handling process scheduling, memory management, and device communication.

A process is a program in execution. Each process has its own memory space, program counter, and set of registers, which is what allows the operating system to run multiple programs at once without them interfering with each other. A thread, by contrast, is a lightweight unit of execution within a process. Multiple threads within the same process share the same memory space, which makes communication between them fast but also introduces the risk of race conditions.

Process scheduling determines which process runs on the CPU at any given moment. Common scheduling algorithms include First Come First Served, Shortest Job First, Round Robin, and Priority Scheduling. Round Robin is widely used in time sharing systems because it gives each process a fixed time slice, ensuring fairness and preventing any single process from monopolizing the CPU.

Memory management is another core responsibility of the operating system. Paging divides memory into fixed size blocks called pages, which are mapped to physical memory frames. This allows a process to use more memory than physically exists by swapping pages in and out of disk storage, a technique known as virtual memory. Segmentation, on the other hand, divides memory based on logical divisions like functions or data structures rather than fixed size blocks.

Deadlock occurs when two or more processes are each waiting for a resource held by the other, and neither can proceed. Four conditions must hold simultaneously for a deadlock to occur: mutual exclusion, hold and wait, no preemption, and circular wait. Operating systems handle deadlock through prevention, avoidance, detection, or simply ignoring the problem and letting the system recover through a restart, which is the approach most consumer operating systems actually take.

Synchronization primitives like mutexes and semaphores exist to prevent race conditions when multiple threads access shared data. A mutex allows only one thread to access a critical section at a time. A semaphore is more general, maintaining a counter that allows a fixed number of threads to access a resource concurrently, which is useful when managing a pool of limited resources like database connections.
